# PiContextLab development

Improve native Pi context/tool policies; retain the retail investigation client and honest evidence.
Read the acceptance specification and relevant complete source before changes.

- Development source and Git operations may use the desktop. All dependency
  installs, compilation, tests, browser runs and model inference use the
  authorized experiment server. Use only bounded CPU resources unless the user
  changes the current constraint. Do not launch large GPU studies.
- Pin all direct dependencies and preserve the lock. Use npm with lifecycle
  scripts disabled. Keep the original upstream research clone and old environments unchanged. The user explicitly authorized a framework fork: edit the MIT-licensed fixed core under vendor/pi-agent-core, preserve provenance, compare against the unmodified1.6.0 alias, and run both core/application checks on the server.
- Pi provides the agent loop and model adapters. The application owns dataset
  identities, metric semantics, durable jobs, quotas and evidence validation.
  Do not substitute a handwritten tool loop for the actual Pi runtime.
- Validate external inputs at their boundaries. Keep TypeScript strict and avoid
  any. Never use eval, arbitrary model-generated shell commands, or unrestricted
  SQL for the investigation tools.
- Test business arithmetic independently from the compiler under test. Record
  real model results separately from scripted providers and engine tests.
- Never invent deployment, customers, throughput, model accuracy or human review.
  Preserve failed runs and charged unknown calls. Do not reopen closed budgets.
- No changes to the personal homepage, existing automation schedule, unrelated
  repositories, issues, external comments or upstream PRs for this project.
- Do not spawn assistant subagents without explicit user authorization.
