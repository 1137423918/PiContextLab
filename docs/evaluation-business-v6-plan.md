# core6 新业务集成：运行前方案

本方案在真实请求前提交，配合 [冻结协议](../examples/business-v6-protocol.json)。对象为已经发布的contextlab.6，补充真实业务任务上的协议/算术集成证据，不重跑旧v1/v2/v4源审计或ToolRet质量研究，也不调整算法。

两项此前未运行的比较：2011年四月/五月returns按country Top8；2011年二月两个14天半月net_sales按stock_code Top12。问题完整写出四个边界、指标、口径、维度与数量。每项分别使用完整上下文64KiB和预算上下文16KiB，案例间反转顺序；不启用字段搜索。二者预算不相同，结果不是同预算公平算法准确率对照。

Pi实际调用官方DeepSeek API的deepseek-flash，显式关闭thinking、temperature=0、内部重试0。每任务最多6次请求、每次最多1,024输出token、超时20秒；四个任务合计最多24次请求/24,576输出token。失败、超时和未知尝试均保留，不追加质量重试或扩大上限。剩余固定任务继续执行，partial checkpoint不覆盖为成功。

Python CSV/Decimal程序独立读取冻结541,909行CSV，计算各期间总金额及所有维度分组。它不依赖DuckDB/JS计算器；这增加新范围的算术核对，并不重复验证Excel转换。答案只进入评分器，不进入模型问题或工具。CPU预检先把同任务的确定性工具结果与全部独立分组核对，再通过合成反例检查评分器，之后才允许发出请求。

通过要求：封存报告包含准确比较与维度/limit；证据哈希及来源身份有效；总额、每个Top组、剩余组与总变化都匹配独立oracle；不存在遗漏的更大绝对变化组。仅有report/completed状态不足以通过。数值说明和因果叙述不评分，报告仍未人工审核。错误维度、缺少证据、部分结果或缺少报告都计失败。

记录每条实际模型输入、durable预留、返回usage与失败。累计input包括cacheRead/cacheWrite；费用是冻结模型单价下的估计，不是账单。上下文JSON字节、实际token、spill/recall与索引cache统计分开报告。若整个真实任务未触发超预算，这只能验证低压力业务集成，不支持压缩效果结论。

源码先通过无密钥服务器预检并公开提交，再记录该提交到实际运行协议。源码包改为只含构建源码、文档、协议和必要oracle夹具；历史结果及archive不嵌套，原冻结包不修改。服务器阶段保持2个CPU与资源上限，不部署本地模型、不使用GPU。结果无论好坏都留存，不以小样本推导总体成功率、端到端速度或普遍省token。
